# Magazine Comic Viewer Helper

[![Build Status](https://github.com/kuchida1981/comic-viewer-helper/actions/workflows/deploy.yml/badge.svg?branch=master)](https://github.com/kuchida1981/comic-viewer-helper/actions/workflows/deploy.yml)

特定の漫画閲覧サイト向けのTampermonkey/Greasemonkey用ユーザースクリプトです。
画像をブラウザのビューポートサイズに合わせて自動調整し、画像単位での快適なスクロール移動を可能にします。

## 主な機能

*   **続きから読める（レジューム機能）**: 前回読んでいたページを自動記憶。次に開いたとき「続きから読む？」と確認するので、どこまで読んだか探す手間がなくなります。
*   **紙の雑誌のように読める（見開き表示）**: 単ページと見開きをワンキーで切り替え。`d` キー1つで、実際の雑誌をめくるような読書体験を実現します。
*   **今どのへんかひと目でわかる（プログレスバー）**: 読書の進捗状況をビジュアルで確認。長編作品でも安心して読み進められます。
*   **手を止めずにページを移動できる（キーボードナビゲーション）**: `j` / `k`、矢印キー、スペースキーなど直感的なショートカットで、リズムよくページをめくれます。
*   **どんな画面サイズでも最適表示（レスポンシブ調整）**: ブラウザウィンドウのサイズに合わせて画像を自動調整。フルスクリーンから小さなウィンドウまで、常に読みやすいサイズで表示されます。

## インストール方法

1.  ブラウザに [Tampermonkey](https://www.tampermonkey.net/) などのユーザースクリプトマネージャー拡張機能をインストールします。
2.  以下のいずれかのリンクを開いて、スクリプトをインストールします：
    - **[安定版 (推奨)](https://raw.githubusercontent.com/kuchida1981/comic-viewer-helper/stable/comic-viewer-helper.user.js)**
    - **[開発版 (最新)](https://raw.githubusercontent.com/kuchida1981/comic-viewer-helper/unstable/comic-viewer-helper.user.js)**
3.  対応するサイトにアクセスすると自動的に有効になります。

## 使い方

スクリプトが有効なページでは、以下の操作が可能です。

### キーボードショートカット

| 動作 | キー |
| :--- | :--- |
| **次の画像へ** | `↓` `→` `PageDown` `Space` `j` |
| **前の画像へ** | `↑` `←` `PageUp` `Shift + Space` `k` |
| **見開き表示の切り替え** | `d` |

### 画面UI

画面右下に表示されるパネルから以下の操作ができます。**パネルはドラッグ可能**で、マウスで好きな位置に移動できます。

*   **ページカウンター**: 現在の画像位置 / 総画像数を表示
*   **見開き切替 (Spread)**: 単ページ表示と見開き表示を切り替えます（`d` キーでも切り替え可能）
*   **<<**: 最初の画像へ移動
*   **<**: 前の画像へ移動
*   **>**: 次の画像へ移動
*   **>>**: 最後の画像へ移動

## 動作対象サイト

*   `https://something/magazine/*`
*   `https://something/fanzine/*`

※ スクリプト内の `@match` 設定で対象ドメインは変更可能です。

## 技術仕様

*   対象コンテナセレクタ: `#post-comic`
*   対象画像セレクタ: `#post-comic img`

## 開発者向け情報

### アーキテクチャ

アプリケーションはレイヤードアーキテクチャを採用しており、各層の責務が明確に分離されています。

```
+------------------------------------------+
|                   App                    |
|      (エントリーポイント / 初期化)        |
+----------+-------------------+-----------+
           |                   |
    +------+------+    +-------+------+
    |  Managers   |    |    Store     |
    | - Navigator |    | (中央状態    |
    | - UIManager |    |   管理)      |
    | - Resume... |    +--------------+
    +------+------+
           |
    +------+------+     +----------------+
    |  Adapters   |     |   logic.ts     |
    | (サイト固有 |     | (純粋関数のみ  |
    |  DOM抽象化) |     |  DOM依存なし)  |
    +------+------+     +----------------+
           |
        [DOM]
```

- **App**: エントリーポイント。各コンポーネントの初期化とライフサイクル管理を担当。
- **Managers**: 機能ごとのロジック（Navigator=ページ移動、UIManager=UI操作、ResumeManager=再開機能など）。
- **Store**: アプリケーションの中央状態管理。
- **Adapters**: サイト固有のDOM構造を抽象化し、Managerからサイト依存を切り離す。
- **logic.ts**: DOMに依存しない純粋関数のみで構成。単体テストが容易で100%カバレッジを維持。

### ⚠️ 注意: ビルド済みファイルを直接編集しないでください
`dist/comic-viewer-helper.user.js` は**ビルド成果物**です。手動で編集しても、次のビルド時に上書きされます。
コードの修正は `src/` ディレクトリ内のファイルに対して行い、ビルドコマンドを実行してください。

### 準備
1. 依存関係のインストール:
   ```bash
   npm install
   ```
   ※ `npm install` 実行時に Git フック (husky) が自動的にセットアップされます。
   もし手動でセットアップし直す必要がある場合は、以下のコマンドを実行してください：
   ```bash
   npx husky
   ```

### 開発ワークフロー

このプロジェクトでは、Git フック (husky) を使用して、コミット前に自動的に品質チェックを行っています。

`git commit` 実行時に、以下のチェックが自動的に実行されます：
1. `npm run lint` - ESLint チェック
2. `npm run check-types` - TypeScript 型チェック
3. `npm test` - ユニットテスト（コアロジックは100%カバレッジ必須）
4. `npm run build` - ビルドの検証
5. `openspec validate --strict --all` - 仕様書の検証

これらのチェックのいずれかが失敗した場合、コミットは中断されます。

プルリクエストを作成する前に、手動で全ての品質チェックが通ることを確認したい場合は、以下のコマンドを実行してください：

```bash
make all
# または
make pre-pr
```

このコマンドは以下を実行します：
1. `npm test` - ユニットテスト（コアロジックは100%カバレッジ必須）
2. `npm run lint` - ESLint チェック
3. `npm run check-types` - TypeScript 型チェック
4. `openspec validate --strict --all` - 仕様書の検証
5. `IS_UNSTABLE=true npm run build` - ビルドの検証

**全てのチェックが成功してから** プルリクエストを作成してください。

### 設計思想と品質へのこだわり

このプロジェクトは個人的な趣味プロジェクトですが、プロフェッショナルな品質基準を適用しています。

#### 仕様駆動開発（OpenSpec）

すべての機能追加・修正は [OpenSpec](https://github.com/kuchida1981/openspec) ワークフローに基づいて行われます。要件定義 → シナリオ設計 → タスク作成 → 実装という順序を守ることで、「なぜそのコードが書かれたか」を常に追跡可能にしています。

#### ロジック層の 100% テストカバレッジ

`src/logic.ts` はアプリケーションの中核を担う純粋関数群です。DOM への依存を完全に排除し、**カバレッジ 100%** を維持することで、リファクタリング時の安全性とロジックの信頼性を保証しています。

### ビルド
ソースコードから `dist/comic-viewer-helper.user.js` を生成します：
```bash
npm run build
```
※ `dist/` ディレクトリは Git の管理から除外されています。ビルド成果物は、masterブランチへのプッシュ時に `unstable` ブランチへ、またバージョンタグのプッシュ時に `stable` ブランチへ GitHub Actions によって自動的にデプロイされます。

### テスト
Vitest を使用してユニットテストを実行します（カバレッジレポートも生成されます）：
```bash
npm test
```
コアロジック (`src/logic.js`) は **カバレッジ 100%** を維持しています。

### 型チェック
JSDoc と TypeScript を使用した静的型解析を実行します：
```bash
npm run check-types
```

### リンティング
ESLint を使用してコードスタイルと UserScript メタデータの検証を実行します：
```bash
npm run lint
```
