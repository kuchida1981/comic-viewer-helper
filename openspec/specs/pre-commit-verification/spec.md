## Purpose

コミット前にコード品質（Lint, 型チェック, テスト, ビルド）および OpenSpec の整合性を自動検証することで、プロジェクトの健全性を維持し、不具合の混入を早期に防止する。

## Requirements

### Requirement: プロジェクト全体の Lint 検証
システムは、プロジェクトの `src` ディレクトリ配下の TypeScript ファイルに対して ESLint を実行し、規約違反がないことを確認しなければならない (MUST)。
検証が成功した場合は出力を抑制し、失敗した場合のみエラー内容を表示しなければならない。

#### Scenario: Lint エラーがある場合のコミット阻止
- **WHEN** プロジェクト内に ESLint エラーが含まれた状態で `git commit` を実行したとき
- **THEN** コミットが中断され、エラー内容が表示されること

### Requirement: プロジェクト全体の型チェック
システムは、コミット前にプロジェクト全体の TypeScript 型チェック (`tsc`) を実行し、型エラーがないことを保証しなければならない (MUST)。
検証が成功した場合は出力を抑制し、失敗した場合のみ型エラーの詳細を表示しなければならない。

#### Scenario: 型エラーがある場合のコミット阻止
- **WHEN** プロジェクト内に型エラーが存在する状態で `git commit` を実行したとき
- **THEN** コミットが中断され、型エラーの詳細が表示されること

### Requirement: 全件ユニットテストのパス
システムは、コミット前に Vitest による全件ユニットテストを実行し、すべてのテストがパスすることを確認しなければならない (MUST)。また、設定されたカバレッジ閾値を満たしている必要がある。
検証が成功した場合は出力を抑制し、失敗した場合のみテスト結果またはカバレッジ不足を表示しなければならない。

#### Scenario: テスト失敗時のコミット阻止
- **WHEN** 失敗するテストが存在する、またはカバレッジ閾値を下回る状態で `git commit` を実行したとき
- **THEN** コミットが中断され、テスト結果またはカバレッジ不足が表示されること

### Requirement: ビルドの成功確認
システムは、コミット前に `npm run build` を実行し、デプロイ用スクリプトが正常に生成できることを確認しなければならない (MUST)。
ビルドが成功した場合は出力を抑制し、失敗した場合のみビルドエラーを表示しなければならない。

#### Scenario: ビルド失敗時のコミット阻止
- **WHEN** ビルドスクリプト（`scripts/build.mjs`）の実行中にエラーが発生した状態で `git commit` を実行したとき
- **THEN** コミットが中断され、ビルドエラーが表示されること

### Requirement: OpenSpec の整合性検証
システムは、コミット前に `openspec validate` を実行し、すべての OpenSpec アーティファクトに整合性の不備がないことを確認しなければならない (MUST)。
検証が成功した場合は出力を抑制し、失敗した場合のみ検証エラーの内容を表示しなければならない。

#### Scenario: OpenSpec 検証失敗時のコミット阻止
- **WHEN** OpenSpec のルール違反や未完了のタスクが残っている状態で `git commit` を実行したとき
- **THEN** コミットが中断され、検証エラーの内容が表示されること

### Requirement: コミット前検証プロセスのドキュメント化
システムは、コミット前検証（Gitフック）が何を行っているか、またそれがプロジェクトのどの品質目標に紐づいているかを開発者ガイドで説明しなければならない (MUST)。
これにより、開発者が自動検証を単なる制約ではなく、品質保証のツールとして理解できるようにする。

#### Scenario: 検証プロセスの説明確認
- **WHEN** 開発者が `README.ja.md` の「開発ワークフロー」セクションを読んだとき
- **THEN** コミット時に実行される各チェック項目（lint, test, build, openspec）とその目的が説明されていること
