## Context

お気に入り一覧モーダル(`FavoritesModal.ts`)は、お気に入りタブに「トレンドセクション(`createTrendSection`)+作品グリッド」を持ち、選択タグ(`selectedTagTexts`)で `filterWorksByTags` により絞り込む。タグ集計は `calculateTrends(favorites, limit, pinnedTags, selectedTags)` が担い、`limit = 0` で全件を返す。ビュー切替の既存パターンとして、お気に入り/履歴のタブ切替(`switchTab`)がある。

## Goals / Non-Goals

**Goals:**
- 頻度上位30件のタグを対象にした、頻度に応じた文字サイズのタグクラウドを別ビューとして追加する
- タグクラウドのクリックで、そのタグを選択済みの一覧ビューへ遷移する
- サイズ段階の計算を純粋関数にして単体テストでカバーする

**Non-Goals:**
- 既存トレンドセクションの置き換え・変更
- 円グラフ/棒グラフ等の他形式、外部チャートライブラリの導入
- 検索結果・履歴へのタグクラウド表示(#270)
- 保存データ形式の変更

## Decisions

### 1. ビュー切替はお気に入りパネル内のサブ切替にする
お気に入りタブ内に「一覧 / タグクラウド」のトグルを置き、`favPanel` 内で一覧ビュー(トレンド+グリッド)とクラウドビューの表示を切り替える。モーダルのタブ(お気に入り/履歴)を増やす案は、タグクラウドがお気に入り限定の機能であり、選択タグ状態を共有したいため採用しない。状態は `favoritesView: 'list' | 'cloud'` としてコンポーネント内ローカルに保持する(Store には載せない)。

### 2. 集計は `calculateTrends` を再利用する
`calculateTrends(favorites, TAG_CLOUD_LIMIT)`(`TAG_CLOUD_LIMIT = 30`)で出現件数上位のタグを件数付きで取得する。新規の集計ロジックは作らない。ユーザーによる件数の切替UIは設けない(件数が多すぎるという動作確認結果を受けた固定上限。しきい値方式は表示数がデータ依存になるため採用しない)。クラウドではピン留め・選択による並べ替えを使わず、タグ名順(同順位は件数降順)の安定した並びにして位置が頻繁に動かないようにする。並べ替えが必要な場合は表示側で行い、`logic.ts` の既存関数の挙動は変更しない。

### 3. サイズ段階は `logic.ts` の純粋関数で計算する
`calculateTagCloudLevel(count, min, max, levels = 5): number` を追加し、1〜`levels` の整数段階を返す。線形スケール(`min === max` の場合は中間段階)とする。DOM に依存せず、境界値(min/max/同数/単一タグ)をテストして 100% カバレッジを維持する。CSS 側は `comic-helper-tag-cloud-item--level-N` のクラスでフォントサイズを定義する。

### 4. クリック時の絞り込みは既存の選択タグ状態を再利用する
クラウドのタグクリックで `selectedTagTexts.add(tagText)` し、`favoritesView = 'list'` に切り替えて `rerenderFavoritesPanel()` を呼ぶ。既存の `filterWorksByTags` とトレンドの選択表示がそのまま機能する。

### 5. お気に入り更新時の挙動
`updateFavorites` は従来どおり選択タグをリセットする。表示中のビューは維持し、クラウドビュー表示中なら最新データで再描画する。

## Risks / Trade-offs

- 上位30件に絞るため、クラウドが極端に長くなることはない。一方で出現件数の少ないタグ(特に1件のみのタグ)はクラウドに表示されない → 全タグの確認は一覧ビューのトレンド(すべて表示)で行える
- 線形スケールは、極端に多い1タグがあると他が小さく揃う → まず線形で実装し、実データで見づらければ対数スケールを別途検討する
- 既存の `FavoritesModal.ts` が大きくなる → タグクラウド描画は `createTagCloudSection` として関数分離する
