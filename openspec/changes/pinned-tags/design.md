## Context

現在、お気に入り画面（Library）の「あなたの好み（Trends）」セクションでは、お気に入り作品に含まれるタグの出現回数上位10件（または全件）が表示されます。ユーザーが頻繁に使用する特定のタグへ素早くアクセスしたいというニーズに応えるため、タグをリストの先頭に固定（ピン留め）できる機能を導入します。

## Goals / Non-Goals

**Goals:**
- タグをピン留めし、出現回数に関わらずリストの先頭に表示する。
- ピン留めの状態をブラウザ（`GM_storage`）に永続化する。
- タグチップ上で直感的にピン留め/解除ができるUIを提供する。

**Non-Goals:**
- ピン留めされたタグ自体の並び替え機能（ピン留め内での優先順位付け）。ピン留め内では出現回数順または追加順を維持します。
- 検索画面など、ライブラリ以外でのタグピン留め。

## Decisions

### 1. データ構造の変更
`StoreState` に `pinnedTags: string[]` を追加します。
- **理由**: タグ名（文字列）の配列として保持することで、永続化と検索が容易になります。
- **代替案**: `Tag` オブジェクトの配列。しかし、タグのメタデータ（hrefやtype）は作品から動的に取得されるため、名前だけで十分です。

### 2. ロジック層 (`src/logic.ts`) の更新
`calculateTrends` 関数を拡張し、ピン留め状態を考慮するようにします。
- **変更内容**: 
  - 引数に `pinnedTags: string[]` を追加。
  - 戻り値を `Array<{ tag: Tag; count: number; isPinned: boolean }>` に変更。
  - ソートロジック: `isPinned` が `true` のものを最優先し、その中で出現回数順にソート。次に `isPinned` が `false` のものを出現回数順にソート。
- **理由**: UI層で複雑なソートを行うよりも、純粋関数であるロジック層で処理することで、テストが容易になり、UIの実装がシンプルになります。

### 3. UI コンポーネントの構造変更
`FavoritesModal.ts` におけるタグチップの構造を、ボタンの入れ子を避けるために変更します。
- **構造**:
  ```html
  <div class="comic-helper-tag-chip-container">
    <button class="comic-helper-tag-chip">Tag Name (Count)</button>
    <button class="comic-helper-tag-pin">📌</button>
  </div>
  ```
- **理由**: HTMLの仕様上、`button` 要素の中に `button` を入れることはできません。フィルタリング用のボタンとピン留め用のボタンを分けることで、アクセシビリティとクリックの正確性を確保します。

### 4. 永続化の仕組み
`Store.ts` の `STORAGE_KEYS` に `PINNED_TAGS` を追加し、既存の `_persistSearchRelatedChanges` 内で他のホスト固有データ（お気に入りなど）と同様に保存します。
- **キー**: `comic-viewer-helper-pinned-tags-${hostname}`
- **理由**: サイト（ホスト）ごとに利用されるタグが異なるため、ホストごとに保存するのが適切です。

## Risks / Trade-offs

- **[Risk]** ピン留めされたタグが多すぎると、通常のトレンドタグ（出現回数順）が隠れてしまう。
  - **Mitigation**: ピン留めされたタグは「上位10件」の制限とは別枠で表示するか、制限内であっても視覚的に区別できるようにします。
- **[Trade-off]** タグ名のみでピン留めを管理するため、同じ名前でタイプが異なるタグ（例：アーティスト名の「A」とジャンル名の「A」）が区別できない。
  - **Decision**: 本スクリプトが対象とするサイトの特性上、タグ名の重複は稀であり、実装のシンプルさを優先して名前のみで管理します。
