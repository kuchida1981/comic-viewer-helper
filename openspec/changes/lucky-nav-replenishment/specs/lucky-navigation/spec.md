## MODIFIED Requirements

### Requirement: 関連作品へのランダム遷移
システムは、現在表示されている作品の関連作品リストおよび検索結果のキャッシュから、対象となる作品を抽出し、その中からランダムに1つを選択して遷移する機能を提供しなければならない (SHALL)。
対象作品の抽出ルールは以下の通りとする：
- `metadata.relatedWorks` からは `isPrivate` でない作品を抽出する。
- 検索キャッシュ (`SearchCache`) が存在する場合、TTL (1時間) の経過に関わらず、その結果 (`results`) を全て抽出対象とする。
- 抽出された作品リストは、URL (`href`) に基づいて重複を排除する（バイアスを避けるため）。
- 抽出された作品リストから、現在のページ（正規化済み）および閲覧履歴 (`lucky-history`) に含まれる作品を除外する。
- 履歴による除外を行った結果、候補が空になった場合は、現在のページ（正規化済み）のみを唯一の除外対象として再抽選を行う（フォールバック）。
- **[MODIFIED]** 候補が不足している場合（例：5件未満）、システムは遷移前に「候補プールの能動的補充」を試みなければならない。補充が完了した後に、更新されたリストから再抽選を行う。

#### Scenario: 履歴を考慮した遷移
- **WHEN** ユーザーが「おすすめ（ランダム）」ボタンをクリックする
- **AND** 関連作品または検索キャッシュに対象作品が複数存在する
- **THEN** システムは `lucky-history` に含まれる作品および現在のページを候補から除外して抽選を行う
- **AND** 除外後の候補からランダムに1つ選択して遷移する

#### Scenario: 履歴により候補が全滅した場合のフォールバック
- **WHEN** ユーザーが「おすすめ（ランダム）」ボタンをクリックする
- **AND** 全ての関連作品および検索キャッシュの作品が `lucky-history` に含まれている
- **THEN** システムは現在のページのみを除外対象とし、他の全ての作品からランダムに1つ選択して遷移する

#### Scenario: 関連作品が存在し検索キャッシュがない場合の遷移
- **WHEN** ユーザーが「おすすめ（ランダム）」ボタンをクリックする
- **AND** 検索キャッシュが存在しない
- **THEN** システムは `metadata.relatedWorks` リストから `isPrivate` でない作品のみを対象とし、`lucky-history` および現在のページを除外した上で、ランダムに1つ選択して遷移する

#### Scenario: 関連作品と検索キャッシュが存在する場合の遷移
- **WHEN** ユーザーが「おすすめ（ランダム）」ボタンをクリックする
- **AND** 検索キャッシュが存在する（TTL経過後も含む）
- **THEN** システムは `metadata.relatedWorks` (非公開除く) と検索キャッシュの結果をマージし、`lucky-history` および現在のページを除外した上で、URLで重複排除したリストからランダムに1つ選択して遷移する

#### Scenario: 候補不足時の補充を伴う遷移
- **WHEN** ユーザーが「おすすめ（ランダム）」ボタンをクリックする
- **AND** フィルタリング後の候補数が 5件 未満である
- **THEN** システムは作品の補充（Discovery Management）を開始し、完了を待機する
- **AND** 補充された作品を含む新しい候補リストからランダムに1つ選択して遷移する

### Requirement: 補充中の視覚的フィードバック
システムは、作品の補充が行われている間、ユーザーに対して処理中であることを示す視覚的フィードバックを提供しなければならない (SHALL)。

#### Scenario: 🎲 ボタンのローディング表示
- **WHEN** ランダムジャンプのための作品補充（fetch）が開始される
- **THEN** UI上の「おすすめ（ランダム）」ボタン（🎲）はローディング状態（無効化、またはアイコンの変化）となり、ユーザーに待機を促す
- **AND** 遷移が開始されるか補充が完了した時点で、ローディング状態を解除する
