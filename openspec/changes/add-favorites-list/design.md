## Context

現在、本拡張機能には「お気に入り」の登録・解除機能（`Store.favorites` への保存と `localStorage` への永続化）が実装されています。しかし、登録した作品を一覧で表示し、そこから過去の作品へ戻るためのUIが存在しません。ユーザーは現在閲覧中の作品がお気に入りかどうかは判断できますが、お気に入りリスト全体を管理・閲覧する手段が欠けています。

## Goals / Non-Goals

**Goals:**
- お気に入り作品の一覧を表示する新しいモーダルUIの提供。
- サムネイルとタイトルによる視覚的なリスト表示。
- 一覧からの直接的な作品遷移（リンク）と削除機能。
- ナビゲーションボタンおよびショートカットキーによるシームレスなアクセス。

**Non-Goals:**
- お気に入り作品の検索機能（今回はリスト表示のみ）。
- デバイス間のお気に入り同期機能。
- お気に入りのカテゴリ分けやタグ付け機能。

## Decisions

### 1. 新しいモーダルコンポーネント `FavoritesModal.ts` の作成
既存の `SearchModal.ts` のグリッド表示ロジックを再利用し、一貫性のあるUIを提供します。
- **理由**: `SearchModal` はすでにサムネイルとタイトルのグリッド表示、ページ遷移のハンドリングを実装しており、コードの重複を避けつつ、ユーザーにとって馴染みのある操作感を提供できるため。
- **代案**: `MetadataModal` にリストを埋め込む案もありましたが、情報量が多くなることが予想されるため、独立したモーダルとして実装します。

### 2. `StoreState` へのフラグ追加
`isFavoritesModalOpen: boolean` を `StoreState` に追加し、`Store` 経由で状態を管理します。
- **理由**: 既存の `MetadataModal` や `SearchModal` と同様の管理パターンに従うことで、`UIManager` での一貫したモーダル制御が可能になるため。

### 3. ショートカットキー `l` (List) の割り当て
お気に入り一覧を表示するためのキーとして `l` を採用します。
- **理由**: 'Favorites' の 'f' はすでにフルスクリーン（Fullscreen）に割り当てられており、'List' の頭文字である 'l' が直感的であるため。

### 4. `NavigationButtons` へのアイコン追加
既存のナビゲーションボタン群に「📚」（または適切なSVGアイコン）を追加します。
- **理由**: マウス操作ユーザーにとっても発見しやすく、既存のツールバーとの親和性が高いため。

## Risks / Trade-offs

- **[Risk]** お気に入りの数が多い場合のパフォーマンス低下
  - **Mitigation**: `SearchModal` と同様に、画像に `loading="lazy"` を指定し、レンダリング負荷を軽減します。初期実装ではページネーションは行わず、全件表示としますが、将来的に数千件規模になる場合はページネーションの導入を検討します。
- **[Trade-off]** `localStorage` の容量制限
  - **Mitigation**: 保存されるのは `RelatedWork` オブジェクト（タイトル、URL、サムネイルURL）の配列のみであり、通常の利用範囲ではブラウザの `localStorage` 制限（通常5MB程度）に達する可能性は低いです。
