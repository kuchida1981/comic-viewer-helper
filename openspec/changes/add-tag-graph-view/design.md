# Design

## Context

- `FavoritesModal.ts` は一覧とクラウドの2ビューを持ち、DOM を差し替えて再描画する。種類フィルタ UI は `createTagTypeChips` にある
- `UIManager` はストアのあらゆる状態変化で `updateFavorites` を呼ぶ。毎回作り直すとグラフの配置がリセットされる
- モーダルの overlay と content がホイールイベントを制御している
- 実行時依存はなく、`src/logic.ts` は純粋関数のみで 100% カバレッジが必要

## Goals / Non-Goals

**Goals:** 依存を増やさず、テスト可能な形で、動きのあるグラフを実現する。後続の #294 のためにノード数上限を引数にする。

**Non-Goals:** 数百ノード規模の性能、タブレット・スマートフォンのタッチ操作、配置の永続化。

## Decisions

1. **描画は SVG**。50 ノード・150 線程度なら十分で、jsdom でテストでき、CSS で色や強調を扱える。Canvas は当たり判定とテストの手間が大きい。
2. **シミュレーションは自前実装**。全ペアの反発、線のばね、中心への引力、減衰する温度（alpha）だけで足りる。`d3-force` は依存と配布サイズが増えるため見送る。
3. **ロジックと描画の分離**。グラフ構築と1ステップ分の計算は `logic.ts` の純粋関数にする。初期配置は乱数を使わず決定的にする（テストの再現性）。描画・イベント・アニメーションループは新しい `ui/components/TagGraphView.ts` に置き、`update` と `setActive` と `destroy` を公開する。
4. **ノードと線の選定**。ノードは件数上位 50（`calculateTrends` を利用、ピン留めと選択は考慮しない）。1作品内の同名タグは1回と数える。線は共起 2 以上を Jaccard 係数で順位付けし、いずれかの端点の上位 3 本に入るものを残す。孤立ノードは中心への引力で視界に留める。
5. **差分更新**。`update` はノード・件数・線から署名を作り、同じなら何もしない。変わる場合は既存ノードの座標を引き継ぐ。
6. **アニメーションの停止**。alpha が閾値未満、非アクティブ、`destroy` のいずれかで `requestAnimationFrame` を止める。ドラッグ中は alpha を保つ。`UIManager` はモーダル削除時にモーダルの `destroy` を呼ぶ。
7. **操作**。Pointer Events を使い、移動が数 px 未満ならクリック、それ以上ならドラッグとする。ズームと位置は SVG 内のグループの transform で表現し、`wheel` は `preventDefault` と `stopPropagation` をグラフ側で行う。ノードはキーボードでもフォーカスして Enter で選択できるようにする。
8. **種類フィルタは独立した状態**。クラウドと共有すると `favorites-tag-cloud` の「クラウドの表示にのみ作用する」要件を変える必要がある。UI と `toggleTagTypeFilter` は再利用する。

## Risks / Trade-offs

- [数値（上限 50、共起 2、上位 3、力の係数）が実データに合わない] → 定数にまとめ、ユーザー確認で調整する。spec に書いた値を変える場合は spec も更新する
- [お気に入りが少ないと線がほとんど出ない] → 孤立ノードとして表示する。確認結果次第で閾値を見直す
- [長いタグ名のラベルが重なる] → 反発の距離にノード半径を加味し、ズームで読めるようにする
- [`logic.ts` が肥大化する] → 今回は既存の方針に合わせる。分割は ESLint の層構成の変更を伴うため別課題とする
- [既存の `updateFavorites` は状態変化のたびに一覧のタグ選択を解除する] → 本変更では直さない。グラフは差分判定で影響を避ける
