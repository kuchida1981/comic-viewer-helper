## Context

現在の `README.md` および `README.ja.md` には、husky による Git フックのセットアップと、コミット時に自動実行される品質チェックについての説明が不足しています。
`npm install` 実行時に `prepare` スクリプトを介して husky が自動的にセットアップされますが、この挙動が明示されていないため、新しい開発者がワークフローを理解しにくい状態です。

## Goals / Non-Goals

**Goals:**
- 開発者ガイドに husky のセットアップ手順を追記する。
- 開発者に対して、コミット時に自動検証が走ることを説明し、その目的を理解してもらう。

**Non-Goals:**
- husky の設定そのものの変更（`.husky/pre-commit` の変更など）。
- 既存のテスト、リンター、ビルドスクリプトの動作変更。

## Decisions

### 1. 「準備」セクションへの追記
`npm install` が husky のセットアップを兼ねていることを明記します。また、何らかの理由で手動セットアップが必要な場合のコマンド (`npx husky`) を紹介します。

### 2. 「開発ワークフロー」セクションへの追記
コミット時に実行される `lint`, `type check`, `test`, `build`, `openspec validate` の各ステップが Git フック (husky) によって自動化されていることを説明します。

## Risks / Trade-offs

- **[Risk]** ドキュメントが長くなりすぎる。
- **[Mitigation]** 簡潔な箇条書きとテーブル形式を使用して、視認性を維持します。
