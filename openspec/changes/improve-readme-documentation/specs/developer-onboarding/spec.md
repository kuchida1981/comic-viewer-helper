## MODIFIED Requirements

### Requirement: 準備手順のドキュメント化
システムは、開発者ガイド（`README.md` および `README.ja.md`）において、開発を始めるための「準備」手順を明確に提示しなければならない (MUST)。
これには、依存関係のインストール (`npm install`) に加えて、git フックのセットアップ (husky) が含まれる必要がある。

#### Scenario: 準備手順の確認
- **WHEN** 開発者が `README.ja.md` の「準備」セクションを読んだとき
- **THEN** 依存関係のインストールコマンドと、husky の手動セットアップコマンドが記載されていること

### Requirement: 開発ワークフローとGitフックの説明
システムは、開発者が変更をコミットする際に自動的に品質チェック（Gitフック）が走ることを、開発者ガイドに明記しなければならない (MUST)。
これにより、開発者がコミット時に発生するチェックの意図を理解できるようにする。

#### Scenario: ワークフロー説明の確認
- **WHEN** 開発者が `README.ja.md` の「開発ワークフロー」セクションを読んだとき
- **THEN** コミット時に `lint`, `test`, `build`, `openspec validate` などのチェックが自動実行される旨の説明があること

## ADDED Requirements

### Requirement: アーキテクチャ図の提示
システムは、開発者ガイドにおいて、アプリケーションのレイヤードアーキテクチャ（Logic, Store, Manager, Adapter）を視覚化した ASCII 図面を提示しなければならない (MUST)。
これにより、新規開発者がコード構造を迅速に把握できるようにする。

#### Scenario: アーキテクチャ図の確認
- **WHEN** 開発者が開発者ガイドを読んだとき
- **THEN** レイヤ間の依存関係を示す ASCII アーキテクチャ図が含まれていること

### Requirement: 設計思想と品質基準の明文化
システムは、開発者ガイドにおいて、プロジェクトの設計思想（Design Philosophy）および品質基準（100% テストカバレッジ、OpenSpec による仕様駆動開発）を明文化しなければならない (MUST)。

#### Scenario: 設計思想セクションの確認
- **WHEN** 開発者が開発者ガイドの「設計思想」セクションを読んだとき
- **THEN** OpenSpec の採用理由と、ロジック層の 100% テストカバレッジへの取り組みについて記述があること
