## Context

現在の `README.md` および `README.ja.md` は、インストールの手順や開発フローなどの最低限の情報を網羅していますが、プロダクトとしての魅力（ユーザー体験の質）や、技術的な卓越性（レイヤードアーキテクチャ、100%テストカバレッジ、OpenSpecによる仕様駆動開発）についての記述が不足しています。

特に、英語版のREADMEは日本語版に比べて情報が少なく、グローバルなコントリビューターを惹きつけるには改善の余地があります。

## Goals / Non-Goals

**Goals:**
- プロダクトの価値（ベネフィット）を強調した機能紹介の追加
- レイヤードアーキテクチャを視覚化するASCII図の導入
- 「設計思想（Design Philosophy）」セクションの新設による品質基準の明文化
- 日本語版と英語版の内容の同期と充実
- プライバシー（対象サイトの非公開）を維持したままの訴求力向上

**Non-Goals:**
- スクリーンショットやGIF動画などの画像資産の追加（本変更ではプレースホルダーの検討に留める）
- アプリケーションコード（ロジックやUI）の変更

## Decisions

### 1. ユーザー機能の「ベネフィット」中心の再定義
単なる「機能」の羅列ではなく、ユーザーがどのような体験を得られるかに焦点を当てた説明を採用します。
- **Rationale**: ユーザーは機能そのものではなく、それによって得られる利便性を求めているため。

### 2. アーキテクチャ図のASCII形式での提供
`GEMINI.md` に記載されている設計指針を視覚化します。
- **Rationale**: 開発者がプロジェクトの構造を瞬時に把握できるようにし、適切な場所へコントリビュートしやすくするため。画像ファイルではなくASCIIを使用することで、メンテナンス性を維持します。

### 3. 設計思想セクションの追加
OpenSpecによる仕様駆動開発と、ロジック層の100%テストカバレッジへのこだわりを明文化します。
- **Rationale**: 趣味のプロジェクトであっても「プロフェッショナルな品質」を求めていることを示し、質の高い開発者の興味を引くため。

### 4. 英語版 README の大幅な拡充
日本語版と同等の「使い方（Usage）」や「ショートカット一覧」を追加します。
- **Rationale**: 英語圏のユーザーやコントリビューターに対しても、日本語版と同等の情報とサポートを提供するため。

## Risks / Trade-offs

- **[Risk]** ドキュメントのボリュームが増え、必要な情報（インストール方法など）にたどり着きにくくなる。
  - **Mitigation**: セクション分けを明確にし、目次を活用して構造化する。
- **[Risk]** サイト名を伏せているため、具体的な使い勝手がイメージしにくい。
  - **Mitigation**: 「スマート・ナビゲーション」などの抽象的だが価値の伝わる言葉選びを行い、操作概念（キーボードショートカットなど）を詳細に説明することで補完する。
- **[Trade-off]** 言語の同期コスト。
  - **Mitigation**: 今回の変更で一度完全に同期させ、以降の変更では両言語の更新を必須とするフローを徹底する。
