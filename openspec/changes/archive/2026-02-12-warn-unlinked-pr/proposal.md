## Why

現在、プルリクエストがGitHubイシューに紐付けられずに作成・マージされることがあり、変更の背景や意図の追跡が困難になる場合があります。開発プロセスの透明性を高め、すべての変更が適切な理由（イシュー）に基づいていることを保証するため、機械的なチェックとテンプレートによる補助が必要です。

## What Changes

- GitHub Actions ワークフローを追加し、PRのタイトルまたは本文にイシュー番号（#123など）が含まれているかを検証します。
- イシュー番号が含まれていない場合、PRに警告を出します。
- `.github/pull_request_template.md` を作成し、PR作成時に必要な情報を定型化するとともに、イシュー番号の記載を促します。

## Capabilities

### New Capabilities
- `pr-issue-link-enforcement`: プルリクエスト作成時にイシュー番号が含まれているか自動チェックし、開発者に通知する機能。
- `pr-template-standardization`: プルリクエスト作成時に必要な情報（背景、目的、イシュー番号、TODOリストなど）をあらかじめ埋め込むテンプレート。

### Modified Capabilities
- なし

## Impact

- GitHub Actions の実行時間（微増）。
- プルリクエスト作成時のUI/UX（テンプレートの自動挿入）。
- 開発ワークフロー（イシュー作成の強制力向上）。
