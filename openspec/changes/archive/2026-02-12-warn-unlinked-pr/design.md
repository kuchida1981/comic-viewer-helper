## Context

現在、プルリクエストが関連するGitHubイシューに紐付けられているかを確認する仕組みがありません。プロジェクトの品質ガイドライン（GEMINI.md）では「GitHub issues drive development」と定められていますが、これを機械的に支援する仕組みが必要です。

## Goals / Non-Goals

**Goals:**
- プルリクエストのタイトルまたは本文にイシュー番号（`#123` 形式）が含まれているかを自動チェックする。
- イシュー番号が欠落している場合に、GitHub Actions のステータスチェック（警告レベル）で通知する。
- プルリクエスト作成時に必要な情報を網羅したテンプレートを提供する。

**Non-Goals:**
- イシューとの紐付けがない場合にマージを完全にブロックすること（今回は警告にとどめる）。
- イシュー番号が実際に存在するかどうかのAPIによる検証（まずは形式的なチェックのみ）。

## Decisions

- **GitHub Actions ワークフロー**: `actions/github-script` を使用して、PRのメタデータをスキャンする軽量なスクリプトを実装します。
  - **Rationale**: 外部のサードパーティActionを導入するよりも、公式の `github-script` を使うほうがセキュリティおよびメンテナンス性の面で優れています。
- **トリガー**: `pull_request` イベントの `opened`, `edited`, `synchronize` で実行します。
- **検証ロジック**: 正規表現 `/#\d+/` を使用して、タイトルと本文の両方をスキャンします。
- **テンプレート形式**: `.github/pull_request_template.md` を配置します。既存の `GEMINI.md` に記載されている開発ワークフローの内容（TODO checklistなど）を盛り込みます。

## Risks / Trade-offs

- **[Risk] 正規表現による誤検知** → **Mitigation**: 単純な `#数字` 形式を基本とし、失敗してもマージをブロックしない（警告のみ）にすることで、開発の妨げにならないようにします。
- **[Risk] テンプレートの重複** → **Mitigation**: すでに README や GEMINI.md にある指針をテンプレートに統合し、一貫性を保ちます。
