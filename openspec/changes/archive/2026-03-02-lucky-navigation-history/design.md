## Context

現在の「おすすめ（ランダム）」機能（Lucky Navigation）は、現在のページや過去数件に閲覧したページを考慮せずに抽選を行うため、同じ作品が連続して表示される問題があります。
また、抽選ロジックが副作用（`window.location.href` の書き換え）を持っており、テストが困難な状態です。

## Goals / Non-Goals

**Goals:**
- 直近20件の閲覧履歴を保持し、同一作品への遷移を抑制する。
- サイト（ドメイン）ごとに独立した履歴を管理する。
- 抽選ロジックを純粋関数化し、テスト可能性を高める。
- 候補が少ない場合でも、少なくとも「現在のページ」以外への遷移を保証する。

**Non-Goals:**
- 全ての閲覧履歴（数千件など）を永続化すること（直近20件に限定）。
- サーバーサイドでの履歴同期（ローカルブラウザ内での完結）。

## Decisions

### 1. URL正規化ロジックの導入
作品を一意に識別するため、`URL` クラスを用いて正規化を行います。
- **内容**: `origin + pathname` のみを使用し、`search`（クエリパラメータ）と `hash` を破棄する。
- **理由**: ページ番号や参照元パラメータが異なっても「同じ作品」として扱う必要があるため。

### 2. Store への履歴状態の追加
`Store` クラスに `luckyHistory: string[]` を追加し、既存の `searchHistory` と同様の仕組みで永続化します。
- **キー名**: `comic-viewer-helper-lucky-history-{host}`
- **保存件数**: `MAX_LUCKY_HISTORY = 20` (FIFO形式)
- **追加タイミング**: 作品ページ読み込み時（アダプターが有効な場合）に、現在のURLを追加。

### 3. 抽選ロジックのリファクタリング (Pure Function 化)
`src/logic.ts` の `jumpToRandomWork` を以下の2つに分離します。
- `pickRandomWork(candidates, luckyHistory, currentUrl)`: 次に遷移すべきURLを返す純粋関数。
- `UIManager` / `Navigator`: `pickRandomWork` の結果を受け取り、`window.location.href` を更新する。

### 4. 段階的なフィルタリング (Fallback)
候補リストから履歴を除外する際、以下の優先度で抽選を試みます。
1. **厳格モード**: `履歴(20件)` + `現在` を除外。
2. **緩和モード**: `直近3件` + `現在` を除外（候補が空になった場合）。
3. **最小モード**: `現在` のみを除外（依然として候補が空の場合）。

## Risks / Trade-offs

- **[Risk] 候補の枯渇** → アダプターが返す関連作品が非常に少ない（例: 1つしかない）場合、履歴が埋まると遷移先がなくなる。
  - **Mitigation**: 上記の「段階的なフィルタリング」により、最悪でも自分以外の関連作品があればそこへ飛ばすようにする。
- **[Trade-off] localStorage の容量** → URL文字列を20件保存するため、微量ながら容量を消費する。
  - **Mitigation**: URLは一般的に短く、20件程度であれば `localStorage` の制限（約5MB）に対して無視できるレベル。
