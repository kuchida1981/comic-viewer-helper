## Context

現在のヘルプモーダルは `src/ui/styles.ts` で定義された固定幅の CSS Grid を使用しています。
```css
.comic-helper-shortcut-row {
  display: grid;
  grid-template-columns: 180px 140px 1fr;
  gap: 12px;
  /* ... */
}
```
この定義により、画面幅が狭い場合に説明文（`1fr`）が表示領域から押し出される、あるいはグリッド全体がオーバーフローする問題が発生します。

## Goals / Non-Goals

**Goals:**
- デスクトップ環境でのブラウザウィンドウのリサイズに対して、ヘルプモーダルのレイアウトが適切に維持されること。
- 画面幅が狭い場合（例: ウィンドウを細長くしている場合）でも、すべてのショートカット情報が読みやすく表示されること。
- 既存の「キー / ラベル / 説明」という情報の分類を損なわないこと。

**Non-Goals:**
- モバイル端末（スマートフォン等）への完全な最適化（プロジェクト方針により対象外）。
- ヘルプモーダル以外の UI コンポーネントのレスポンシブ対応。

## Decisions

### 1. グリッド定義の柔軟化
固定ピクセル指定を避け、`minmax` を活用して柔軟な幅調整を可能にします。
- **Rationale**: デスクトップの標準的な幅では現在の見栄えを維持しつつ、狭くなった際に自動的に縮小させるため。

### 2. メディアクエリによるレイアウト切り替え
ウィンドウ幅が 600px 以下の際、グリッドからスタック形式（または簡略化されたグリッド）へ切り替えます。
- **Rationale**: 3列を維持したまま縮小すると、各列が狭くなりすぎて視認性が極端に低下するため。
- **実装詳細**:
  - `600px` 超: 3列グリッド (Key, Label, Description)
  - `600px` 以下: `flex-direction: column` によるスタック表示。
  - **スペーシング**: `gap: 4px` を用い、要素間の余白を一貫させる。初期実装時の `margin-bottom` は冗長なため削除（レビュー指摘を反映）。

### 3. モーダルコンテンツの幅調整
`width: 80%` に加えて、最小幅 `min-width` や、極端に狭い場合の `width: 95%` への変更を検討します。

## Risks / Trade-offs

- **[Risk]** 列幅を動的にすると、行によって内容の長さが異なる場合にガタつきが発生する可能性がある。
  → **Mitigation**: `grid-template-columns` の最小値を適切に設定し、`minmax` で制御する。
- **[Risk]** メディアクエリの追加により、CSS の管理が複雑になる。
  → **Mitigation**: `src/ui/styles.ts` の既存のスタイル構造に沿って、保守性の高い形式で記述する。
