## Context

- 現在、作品情報は `Metadata` 型で扱われており、関連作品も `RelatedWork` 型で管理されています。
- ランダムジャンプは `src/logic.ts` の `jumpToRandomWork` で行われており、現在は関連作品と検索キャッシュから一律にランダム選択されています。
- お気に入りの永続化には、既存の `Store` と `localStorage` を利用したドメインごとの保存仕組みが活用可能です。

## Goals / Non-Goals

**Goals:**
- 作品単位のお気に入り登録・解除機能の実装。
- お気に入りデータの永続化。
- お気に入り作品を優先（高い確率で出現）させる重み付けランダムジャンプの実装。

**Non-Goals:**
- タグや検索条件のお気に入り登録（Phase 2 で実施）。
- お気に入り一覧管理・削除 UI（Phase 3 で実施）。
- 複数デバイス間での同期機能。

## Decisions

### 1. データ構造の定義
`StoreState` に `favorites: RelatedWork[]` を追加します。`RelatedWork` 型（`title`, `href`, `thumb`）はお気に入り情報の最小セットとして再利用可能です。

### 2. 永続化の仕組み
`STORAGE_KEYS.FAVORITES` を追加し、他の検索関連データと同様に `comic-viewer-helper-favorites-${hostname}` というキーで `localStorage` に保存します。

### 3. 重み付けランダム選択のアルゴリズム（2段階スロット方式）
単一のお気に入り作品が極端に選ばれ続けるのを防ぎ、かつ「お気に入り」が出現しやすくするために、2段階のスロット方式を採用します。

#### アルゴリズム手順：
1. **プールの準備**:
   - `FavoritePool`: お気に入り登録されている全作品のリスト。
   - `DiscoveryPool`: お気に入り、関連作品、検索キャッシュをすべて統合し、重複を除いた全候補のリスト。
2. **スロットの決定**:
   - 乱数（0.0〜1.0）を生成し、`FavoritePool` が空でなければ **25%** の確率で `FavoritePool` から、残りの **75%** の確率で `DiscoveryPool` から作品を選択する。
   - `FavoritePool` が空の場合は、100% の確率で `DiscoveryPool` から選択する。
3. **遷移の実行**:
   - 選択されたプール内から、さらに一様な確率でランダムに1件を選択し、その URL へ遷移を試みる。

この方式により、お気に入り作品が1つしかない場合でも、その作品が選ばれる確率は「25% + (1 / 全候補数 * 75%)」に制限され、ランダムジャンプの意外性を損なうことなく、好みの作品に出会いやすくします。

### 4. UI 統合
`MetadataModal.ts` のタイトル横に「♥」ボタンを追加します。
- ボタンのデザインは CSS (`styles.ts`) で定義し、`comic-helper-favorite-btn` クラスを付与します。
- 登録状態に応じて「♥（塗りつぶし）」と「♡（アウトライン）」を切り替えます。

## Risks / Trade-offs

- **[Risk]** お気に入り作品数が非常に多くなると、`localStorage` の 5MB 制限に抵触する可能性があります。
- **[Mitigation]** 本フェーズでは作品単位の登録のみであるため、数千件規模にならない限り問題になりません。将来的に制限に近づく場合は、古いデータの自動削除やメタデータの削減を検討します。
- **[Trade-off]** 重みを 10 倍に固定しているため、お気に入り作品が 1 つしかない場合はその作品が極端に選ばれやすくなります。
