# Design

## Context

- `buildTagGraph` はノード数の上限を引数で受け取れる。`TagGraphView.update` は渡していない
- `update` は内容が変わると要素を作り直し、残るノードの座標は引き継ぐ。新しいノードはらせん状の初期位置に置く
- 力の係数は50ノードに合わせて調整した値である
- `Store.setState` は購読者に通知し、`UIManager` が `updateFavorites` を呼ぶ。これは一覧ビューのタグ選択を解除する

## Goals / Non-Goals

**Goals:** 50ノードのときの見た目を変えずに、10〜100で使えるようにする。

**Non-Goals:** 100を超えるノード数、ノードの出入りのアニメーション効果。

## Decisions

1. **スライダーは `<input type="range">`** を `FavoritesModal` の種類フィルタの下に置く。`input` で反映し、`change` で保存する（ドラッグ中の書き込みを避ける）。`TagGraphView.update` に上限の引数を足す。
2. **保存はストアの状態を経由しない**。`Store` に読み込みと保存のメソッドを置き、`GM_getValue` / `GM_setValue` を直接使う。`setState` を使うと通知で一覧のタグ選択が解除されるうえ、他にこの値を監視する画面はない。キーはホストを分けない端末共通の設定とし、同期対象のキーに含めない。`UIManager` が初期値と保存の関数をモーダルに渡す。
3. **値の正規化は純粋関数**にして、読み込み時に使う。範囲と刻みの定数も `logic.ts` に置く。
4. **反発はノード数が50を超えたら `50 / ノード数` を掛けて弱める**。配置の広がりはおよそ √(ノード数 × 反発) に比例するため、50のときの広がりを保てる。50以下は現状のまま。
   反発の調整だけでは、まとまりの強いデータで左右にはみ出す（ブラウザで50件でも確認）。そこで、ラベルを含めて表示領域を超えるときだけ全体を縮小する倍率を掛ける。ユーザーのズームとは独立で、収まっていれば1のまま。表示領域は viewBox ではなく実際に見えている範囲（縦横比の差の分だけ広い）を基準にする。毎コマ少しずつ近づけ、ノードのドラッグ中は変えない。力だけで境界に押し戻す案は、端にノードが並んで見た目が崩れるので採らない。
5. **増えるノードの初期位置**は、線でつながる既存ノードの座標の平均に、番号から決まる小さなずれを足す。相手がなければ現状のらせん配置。乱数は使わない。

## Risks / Trade-offs

- [100ノードではラベルが重なる] → ズームで読む。初期値は50のままにする
- [反発を弱めるとノードが重なりやすくなる] → 衝突の反発も含めて係数をブラウザで確認し、必要なら衝突分は弱めない
- [操作中に毎回要素を作り直す] → 値は10段階で、要素数は数百なので許容する
- [配置の計算は1コマあたりノード数の2乗] → 100ノードで約5千組なので許容する
