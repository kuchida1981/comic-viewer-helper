## Context

現在の `RelatedWork` インタフェースとお気に入り保存ロジックは、作品のタイトル、URL、サムネイルのみを保持しており、タグ情報は含まれていません。本デザインでは、このデータ構造を拡張し、お気に入り一覧（Favorites Modal）においてユーザーの好み（頻出タグ）を可視化・活用できるようにします。

## Goals / Non-Goals

**Goals:**
- お気に入り登録時に、その作品のメタデータからタグ情報を抽出し、永続化データに含める。
- お気に入り一覧を表示する際、保存されている全作品のタグを動的に集計し、頻出順に表示する。
- 表示されたトレンドタグをクリックすることで、そのタグを条件とした検索（Discovery）を即座に実行する。
- 既存のタグ情報を持たないお気に入りデータとの互換性を維持する。

**Non-Goals:**
- 閲覧履歴（`luckyHistory` 等）に基づいたタグ集計（今回は「お気に入り」のみを対象とする）。
- 複数のタグを組み合わせた複雑な論理検索（単一タグによるクイック検索を優先する）。
- お気に入りモーダル以外（メインUI等）でのトレンド表示。

## Decisions

- **データ構造の拡張**: `src/types.ts` の `RelatedWork` インタフェースに `tags?: Tag[]` プロパティを追加します。オプション（`?`）とすることで、既存の保存データ読み込み時にエラーが発生するのを防ぎます。
- **保存ロジックの更新**: `UIManager.ts` の `toggleFavorite` メソッドにおいて、新規追加される `currentWork` オブジェクトに `state.metadata.tags` を含めるように変更します。
- **動的な集計アルゴリズム**: `FavoritesModal.ts` 内で集計処理を実装します。
  - `Map<string, { tag: Tag, count: number }>` を使用してタグ名（`text`）をキーにカウントします。
  - 集計結果を `count` の降順でソートし、上位 10 件を抽出します。
  - 集計はモーダルの表示時および作品削除（`onRemove`）による更新時に毎回実行されます。
- **UIコンポーネントの追加**: `FavoritesModal.ts` の `createGrid` とタイトルの間に、トレンド表示用のセクションを挿入します。
  - 各タグはボタン（バッジ形式）として表示し、クリックイベントを付与します。
  - 集計対象のタグが一つもない場合（既存データのみの場合など）は、セクション自体を非表示にします。
- **検索機能との統合**: タグクリック時には `DiscoveryManager.performSearch` を呼び出します。この際、タグの `type`（artist, genre 等）に応じた `SearchContext` を適切に設定します。

## Risks / Trade-offs

- **[Risk] 大量のお気に入りがある場合のパフォーマンス**: お気に入り作品数が非常に多い場合、表示ごとの集計が UI スレッドをブロックする可能性があります。
  - **[Mitigation]**: 数百件程度であれば `reduce` と `sort` による集計コストは無視できるレベルです。将来的にボトルネックとなる場合は、集計結果を `Store` でキャッシュするなどの対応を検討します。
- **[Risk] 既存データの不完全性**: 既存のお気に入りにはタグがないため、トレンドが正確に反映されません。
  - **[Mitigation]**: 探索フェーズでの決定通り、自然に任せる（新規追加分から反映される）方針とします。ユーザーが既存の作品を再度開き、お気に入りを入れ直す（トグルする）ことで情報を更新することも可能です。
- **[Risk] ストレージ容量の増加**: `localStorage` に保存するデータ量が増加します。
  - **[Mitigation]**: タグ情報は文字列の配列であり、一つの作品あたり数十個程度であれば `localStorage` の制限（通常 5MB）に達するリスクは低いです。
