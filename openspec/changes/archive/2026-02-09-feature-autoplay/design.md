## Context

現在のプロジェクトは、`Navigator` がページ遷移を、`Store` がアプリケーションの状態を、`UIManager` がボタンなどのUI表示を管理しています。オートプレイ機能を実現するには、これらの既存コンポーネントを統合し、タイマーベースの制御ロジックを導入する必要があります。

## Goals / Non-Goals

**Goals:**
- 一定時間（5秒）ごとの自動ページ遷移の実装。
- 最終ページ到達時の自動作品ジャンプ（ランダムジャンプ）の実装。
- ユーザーの手動操作（キー入力、クリック、ホイール）によるオートプレイの自動停止。
- 再生状態を `Store` で一元管理し、ページ遷移を跨いで状態を維持する。

**Non-Goals:**
- ユーザーによる再生速度のカスタマイズ機能（今回は固定5秒とする）。
- 特定のページのみをループ再生する機能。
- IndexedDB を用いた高度な再生キューの管理（履歴機能とは切り離して考える）。

## Decisions

### 1. AutoplayManager の新設
`Navigator` にタイマーロジックを直接書くのではなく、`AutoplayManager` クラスを新設して関心を分離します。
- **理由**: `Navigator` は「どうスクロールするか」に専念させ、`AutoplayManager` は「いつスクロールするか（タイミング）」を制御させるため。
- **代替案**: `Navigator` 内に実装する案もありましたが、タイマーのライフサイクル管理や手動操作による割り込み処理が複雑になるため、別クラスが適当と判断しました。

### 2. 再生ループの制御アルゴリズム
`setInterval` ではなく、前回の遷移完了を待ってから次のタイマーを開始する「再帰的 `setTimeout`」方式を採用します。
- **理由**: 画像の読み込み待ちなどで遷移に時間がかかった場合、`setInterval` ではイベントが溜まってしまうリスクがあるため。
- **ロジック**: `setTimeout` -> `Navigator.scrollToImage(1)` を呼ぶ -> その完了を `await` する -> 再度 `setTimeout` をセットする。

### 3. Store での状態管理と永続化
`StoreState` に `isAutoplayEnabled: boolean` を追加し、`localStorage` に保存します。
- **理由**: `jumpToRandomWork` で別ドメインや別ページに遷移した際、`init` 時の `Store` 復元によりオートプレイをシームレスに再開させるため。

### 4. 手動介入の検知
`InputManager` の各種イベントハンドラ（`onKeyDown`, `onMouseDown`, `handleWheel`）に `stopAutoplay()` 呼び出しを追加します。
- **理由**: ユーザーが自分で読み始めたということは、現在の再生速度が合っていないか、特定のページを精読したいサインであるため、安全のために停止するのが一般的です。

## Risks / Trade-offs

- **[Risk] 無限遷移ループ** → [Mitigation] 遷移先が見つからない（関連作品がない）場合は自然に停止するように `jumpToRandomWork` をガードします。また、短時間での連続遷移を制限します。
- **[Risk] パフォーマンスへの影響** → [Mitigation] タイマーはバックグラウンドタブではブラウザにより抑制されますが、基本的にはアクティブな状態での利用を想定しています。
- **[Risk] UIの複雑化** → [Mitigation] 既存のボタン群の中に自然に溶け込むアイコン（▶/||）を採用します。
