## Context

現在、オートプレイの待機時間（秒数）を変更するには GUI パネルの数値入力フィールド（`<input type="number">`）を操作する必要があります。この要素にフォーカスが当たると、`InputManager` が他のキーボードショートカット（ページ送り等）を無視するため、操作性が低下しています。

## Goals / Non-Goals

**Goals:**
- キーボードショートカット `[` および `]` を使用して、オートプレイの待機時間（`autoplayInterval`）を増減できるようにする。
- 変更された待機時間が即座にオートプレイのタイマーに反映されるようにする。
- ヘルプモーダルに新しいショートカットを表示する。

**Non-Goals:**
- オートプレイ以外の機能に対するショートカットの追加。
- 待機時間の増減幅（1秒固定）のカスタマイズ機能。

## Decisions

### 1. ショートカットキーの選定
- **Decision**: `[` (時間を増やす/速度ダウン) および `]` (時間を減らす/速度アップ) を採用。
- **Rationale**: ビデオプレイヤー等で一般的に使用されるキーであり、直感的であるため。

### 2. 状態更新のフロー
- **Decision**: `InputManager` から直接 `Store.setState({ autoplayInterval: newVal })` を呼び出す。
- **Rationale**: `Navigator` クラスが `Store` の `autoplayInterval` を購読しており、変更時に `_resetAutoplayTimer()` を実行する既存の仕組みがあるため、追加の連携ロジックが不要でシンプルである。

### 3. 値のバリデーション
- **Decision**: 1秒〜99秒の範囲に制限する。
- **Rationale**: 既存の UI（数値入力フィールドの min/max）および `Navigator` の実装（3秒未満での警告等）との整合性を保つため。

## Risks / Trade-offs

- **[Risk] キーの競合** → **[Mitigation]** 既存のショートカット（`a`, `d`, `o`, `i`, `f`, `?`, `/`, `p`, `Escape`）およびページ送りキー（`j`, `k` 等）と重複していないことを確認済み。
- **[Trade-off] UIへのフィードバック** → 数値入力フィールドにフォーカスしていない状態で値が変わるが、既存の `UIManager` が `Store` の変更を検知して UI を更新するため、パネルを開いていれば変更は視認できる。
