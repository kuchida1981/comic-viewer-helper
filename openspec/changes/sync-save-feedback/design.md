## Context

現在の `SyncSettings` コンポーネントは、保存ボタンをクリックすると設定を `Store` に反映させるのみであり、その結果に対する視覚的なフィードバックがありません。また、同期処理（Gist への反映）はデバウンスを伴う非同期処理として `SyncManager` が裏側で行っています。

## Goals / Non-Goals

**Goals:**
- 保存ボタン押下時に設定を即座に永続化し、Gist へのアップロードを試行すること。
- 非同期処理の結果を待って、成功または失敗を UI に表示すること。
- ユーザーに明確なフィードバックを提供し、設定に誤り（PAT の無効など）がないか即座に確認可能にすること。

**Non-Goals:**
- 同期設定以外の UI の大幅な変更。
- オフライン時のローカル保存とリモート保存の分離。
- 自動同期ロジックの変更（既存のデバウンスによる同期は維持）。

## Decisions

### 1. SyncManager への明示的な `push()` メソッドの追加
既存の `scheduleUpload()` はデバウンスされており、設定保存時のフィードバック用としては適していません。
- **Rationale**: 保存ボタンをクリックした直後に結果を知りたいため、デバウンスを回避して即座にアップロードを実行し、その Promise を待機できる公開メソッド `push()` を `SyncManager` に追加します。

### 2. SyncSettings コンポーネントの非同期 `onSave` コールバック
- **Decision**: `SyncSettingsProps` の `onSave` を `(config: SyncConfig) => Promise<void>` に変更します。
- **Rationale**: `UIManager` (またはその他の呼び出し元) が `syncManager.push()` を実行して結果を待てるようにし、その状態（Pending / Resolved / Rejected）を UI 側で管理できるようにします。

### 3. UI フィードバックのライフサイクル
- **Decision**: 保存ボタンを無効化し「保存中...」と表示した後、成功時は緑色で「保存しました」と表示し、3秒後に元のステータス表示（最終同期時間）に戻します。
- **Rationale**: フィードバックが永続的に残ると最新の同期状態（エラーなど）が不明になるため、一時的なメッセージとして扱います。

## Risks / Trade-offs

- **[Risk]** 同時に自動同期が発生した場合の衝突。
  → **Mitigation**: `SyncManager` 内で `push()` と `scheduleUpload()` の排他制御、またはデバウンスタイマーのクリアを徹底します。
- **[Risk]** ネットワークエラーによる保存のタイムアウト。
  → **Mitigation**: 適切なタイムアウト処理とエラーメッセージの表示を保証します。
