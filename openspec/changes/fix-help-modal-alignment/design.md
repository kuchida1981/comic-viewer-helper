# Design: fix-help-modal-alignment

## Context

現在のヘルプモーダルは、キーボードショートカット一覧を表示する際、`.comic-helper-shortcut-row` クラスで Flexbox レイアウト（`display: flex` + `justify-content: space-between`）を使用している。各行は3つの要素で構成される：

1. `.comic-helper-shortcut-keys`: キーボードアイコン（1〜5個のキーを含む）
2. `.comic-helper-shortcut-label`: 機能名（例: "次のページ"）
3. `.comic-helper-shortcut-desc`: 説明文（例: "次のページへ移動"）

**問題点**:
- `justify-content: space-between` により、要素が両端と中央に分散配置される
- ラベルと説明文の両方が `flex: 1` であるため、残りスペースを均等に分け合う
- キーの個数（1〜5個）によってキー列の幅が変動し、その結果ラベルと説明文の開始位置がずれる

**具体例**:
```
[j][↓][PgDn][←][Space]  次のページ           次のページへ移動
[d]                     見開き     見開きモードのON/OFF
                        ↑          ↑
                        開始位置がずれる
```

## Goals / Non-Goals

**Goals:**
- すべての行で説明文の開始位置を縦に揃え、視覚的な読みやすさを向上させる
- キーの個数に関わらず、ラベルと説明文が一定の位置から始まるレイアウトを実現する
- 既存のHTMLコンポーネント構造を変更せず、CSSのみで修正する

**Non-Goals:**
- ヘルプモーダルの機能的な動作の変更
- ショートカットの内容や翻訳の変更
- HTMLの構造変更やコンポーネントのリファクタリング

## Decisions

### Decision 1: CSS Grid Layout の採用

**選択**: Flexbox から CSS Grid Layout に変更する

**理由**:
- Grid Layout は列の幅を明示的に制御でき、各列の開始位置を固定できる
- 3列の構造（キー / ラベル / 説明文）に最適
- Flexbox の `space-between` + `flex: 1` の組み合わせでは、キー列の幅変動に伴い後続列の位置がずれる問題を根本的に解決できない

**代替案**:
- Flexbox + 固定幅（`min-width`）: 可能だが、Grid より冗長で柔軟性に欠ける
- Table レイアウト: セマンティック的に不適切

### Decision 2: グリッド列の幅設定

**選択**: `grid-template-columns: 180px 140px 1fr`

**理由**:
- 180px: 最大5個のキー（各約30-35px）を余裕を持って配置できる
- 140px: ラベルテキストの最大幅（「見開きオフセット」「ランダムジャンプ」など）を考慮
- 1fr: 説明文は残りのスペースすべてを使用し、長い説明文も折り返し表示可能

**代替案**:
- `minmax()` を使用: より柔軟だが、今回は固定幅で十分
- すべて固定幅: レスポンシブ性が損なわれる

### Decision 3: gap の使用

**選択**: `gap: 12px` で列間のスペースを制御

**理由**:
- 既存の `margin` 指定（`.comic-helper-shortcut-label { margin: 0 12px; }`）を削除し、Grid の `gap` で統一的にスペーシングを管理
- よりクリーンで保守しやすいコード

### Decision 4: 既存のクラス構造の維持

**選択**: HTMLコンポーネント（`HelpModal.ts`）は変更せず、CSSのみを変更

**理由**:
- レイアウト問題はCSS層で解決可能
- コンポーネントのロジックやテストへの影響を最小限に抑える
- 変更範囲を限定し、リスクを低減

## Risks / Trade-offs

### Risk 1: ブラウザ互換性

[Risk] CSS Grid Layout が古いブラウザでサポートされていない

→ **Mitigation**: Grid Layout は2017年以降主要ブラウザすべてでサポート済み。このプロジェクトのターゲットブラウザ（モダンブラウザ）では問題なし

### Risk 2: 固定幅の制約

[Risk] 180px と 140px の固定幅が、将来的に新しいショートカットやラベルで不足する可能性

→ **Mitigation**:
- 現在のショートカット定義を分析済みで、十分な余裕を持った幅設定
- 必要に応じて後から幅を調整可能（CSSのみの変更）
- 最悪の場合、キー列で折り返し（`flex-wrap: wrap`）、ラベル列でテキスト折り返しが発生するが、視認性は大幅に改善される

### Risk 3: 狭い画面での表示

[Risk] 小さい画面（モバイルなど）でグリッドの固定幅が問題になる可能性

→ **Mitigation**:
- ヘルプモーダルは主にデスクトップ環境で使用される想定
- モーダルの最大幅は既に `max-width: 800px` で制限されており、800px以上の画面では問題なし
- 必要に応じて、将来的にメディアクエリでモバイル用レイアウトを追加可能

### Trade-off: 柔軟性 vs 一貫性

Grid Layout の固定幅により、動的なコンテンツに対する柔軟性は若干低下するが、すべての行で説明文が揃う一貫性と視覚的な読みやすさが大幅に向上する。このユースケースでは、一貫性を優先する判断が適切。
