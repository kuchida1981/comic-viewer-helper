## Context

現在、お気に入り作品に対してのみタグの集計と絞り込みが提供されています。検索結果や閲覧履歴などの他のリストでは、作品ごとのタグ情報が初期状態では欠落しているため、同様の機能が提供できていません。
本設計では、作品タグの永続キャッシュと非同期フェッチメカニズムを導入し、あらゆるリストでタグベースのトレンド表示と絞り込みを実現します。

## Goals / Non-Goals

**Goals:**
- あらゆる作品リスト（検索、履歴、関連作品）でのタグ集計と表示。
- 取得したタグ情報の `GM_storage` への永続化。
- バックグラウンドでの効率的なタグ取得（サイト負荷への配慮）。
- UIコンポーネントの共通化による保守性の向上。

**Non-Goals:**
- キャッシュの容量制限の実装（ユーザー要望により不要）。
- タグ以外の情報のキャッシュ（タイトルやサムネイルは対象外）。
- 複雑なキャッシュ無効化ロジックの実装（基本は永続）。

## Decisions

### 1. Store 構造の拡張
`StoreState` に `workTagsCache: Record<string, Tag[]>` を追加します。
- **理由:** 作品URLをキーにすることで、どの画面からでも即座にタグ情報を参照可能にするため。
- **永続化:** `GM_storage` の既存の仕組みに統合します。

### 2. `TagFetchManager` の新設
非同期フェッチを制御する専用のマネージャーを導入します。
- **制御ロジック:** リスト内の「キャッシュにない作品」を抽出し、キューに入れて順次リクエストを送信します。
- **レート制限:** リクエスト間に 500ms のディレイを挿入し、サーバーへの負荷を抑えます。
- **リアクティブ更新:** 1件取得するごとに Store を更新し、UI が段階的に反映されるようにします。

### 3. `TrendSection` のコンポーネント化
`src/ui/components/TrendSection.ts` を新設し、`FavoritesModal.ts` からロジックを抽出します。
- **インターフェース:** 作品リスト (`RelatedWork[]`) と、タグクリック時のコールバックを受け取る汎用的な設計にします。
- **フィルタリング:** `src/logic.ts` の `filterWorksByTags` を利用し、リストの表示内容を制御します。

### 4. `DefaultAdapter` のパースロジックの再利用
`getMetadata` のパースロジックを、`Document` オブジェクトを引数に取る純粋な関数として抽出します。
- **理由:** `fetch` で取得した HTML を `DOMParser` でパースした結果に対しても、同じロジックでタグを抽出できるようにするため。

## Risks / Trade-offs

- **[Risk] 大量の作品リスト表示時のネットワーク負荷** → **[Mitigation]** シーケンシャルな取得とディレイ（500ms）の挿入により、一度に大量のリクエストが発生するのを防ぎます。
- **[Risk] GM_storage の容量増大** → **[Mitigation]** ユーザーの要望により制限は設けませんが、テキスト情報のみであるため、数千件程度であればブラウザのストレージ制限内（通常数MB〜）に収まると予想されます。
- **[Risk] UI の再レンダリング負荷** → **[Mitigation]** タグ取得のたびにリスト全体を再描画するのではなく、トレンドセクションのみを更新するよう設計します。
